# v0.0.17rc1 -- Multi-Agent Delegation Flow

## Overview

This release adds the first complete Octopus-style multi-agent delegation
loop: a parent session can delegate work to another agent, the child session
runs with isolated context, and the result is injected back into the parent
conversation with navigation between both sessions.

## User-Facing Changes

- Sidebar now hides delegated child sessions behind a `+N delegation hidden`
  row and can reveal them on demand.
- Parent sessions show delegated tool calls and rendered delegation result
  cards.
- Delegation result cards include an `Open session` action that jumps into the
  child session.
- Child delegated sessions show `Delegated from ...` in the top bar and can
  jump back to the parent session.

## Backend/API

- Added `POST /api/sessions/{session_id}/delegations`.
  - Pass `agent` to create a new delegated child session.
  - Pass `delegation_id` to continue an existing delegated child session.
- Added `POST /api/sessions/{session_id}/delegation-result` for result
  injection and deterministic tests.
- Delegation metadata is stored in `sessions.metadata_json`, avoiding a
  database schema migration for existing local installations.
- Background runs launched from an already persisted user message no longer
  duplicate that user message.
- Delegation depth is limited to three levels.

## Notes

- The current API supports the delegation lifecycle and UI navigation. A future
  task should expose a first-class desktop compose action for manual
  delegation instead of relying on model/tool initiation or API calls.
