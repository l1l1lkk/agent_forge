# v0.0.18rc1 -- Agent Settings Dialog

## Overview

This release adds an Octopus-style Agent settings dialog to the desktop UI.
Agents can now be created, edited, and archived from the sidebar instead of
being managed only through API/CLI flows.

## User-Facing Changes

- The plus button beside `Agents` opens an Agent settings dialog.
- The dialog supports:
  - new agent drafts and existing agent selection from a left rail
  - name, icon, description, system prompt, model, and harness selection
  - built-in tool toggles for `ask` and `bg`
  - real connector empty/list state
  - allow/deny tool text areas
  - save/create and archive actions
- Archived agents disappear from the default sidebar list without deleting
  their historical sessions.

## Backend/API

- Extended agent responses with Octopus-style fields backed by
  `tool_policy_json`: `description`, `avatar`, `mcp_servers`, `tool_allow`,
  `tool_deny`, and `archived`.
- Added `GET /api/agents?include_archived=true`.
- Added `POST /api/agents/{id}/archive`.
- Claude runner now passes `tool_allow` as `--allowedTools` and `tool_deny` as
  `--disallowedTools`.
- Desktop IPC now supports proxied `PATCH` requests.

## Verification

- `pytest tests/integration/test_api_agents.py tests/unit/test_runner_registry.py -q`
- `cd desktop && npm.cmd run build`
- Rendered desktop smoke test for opening the dialog, creating an agent,
  editing it, and archiving it.

## Notes

- Built-in tool selections are persisted now. Full MCP server injection for
  `ask` and `bg` remains a follow-up backend integration task.
- Connector enablement is displayed from the real connector API. Agent-scoped
  connector join persistence remains future work.
